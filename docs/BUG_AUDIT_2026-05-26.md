# Bug audit — 2026-05-26

> **Status: closed.** Worked through across v0.4.4–v0.4.7; see `CHANGELOG.md`
> for the fix waves. Kept for the reasoning, not as open work.

Four parallel agents read these files in their entirety looking for bugs:

- `hearthkin.pyw` — main frame, conversation state, distillation coordinator
- `kin_persistence.py` — file I/O, atomic writes, locking, conversation persistence
- `llm_backend.py` — provider dispatch, caching, calibration, tool loop
- `telegram_bot.py` — Telegram surface, history, approval flow

**Total: 100 findings (8 critical, 25 high, 39 medium, 28 low).**

Each finding is an agent-flagged candidate. Most are real bugs; some are speculative ("could fail under X" without confirming X happens). Triage each before acting. The agents were told not to re-flag bugs already fixed in recent releases, so these are net-new (or net-still-broken-despite-fix).

## Recurring themes

1. **Lock-discipline gaps in `_histories` mutations.** The v0.2.28 concurrency sweep added `_histories_lock`, but `/clear`, `/new`, `/reset` command paths and `_load_history_for` skip it. Same-class bugs in shared `_histories` mutation. **3 critical findings.**

2. **Silent encoding failures on read paths.** Multiple files use strict UTF-8 with bare `except: pass` fallback. A `soul.md` or `memory.md` edited in Notepad on Windows can encode as cp1252; load silently returns the default (e.g. DEFAULT_SOUL) — erasing the kin's identity at load time. CLAUDE.md states tolerant decoding as a convention; load_soul/load_memory/load_distill_prompt don't follow it.

3. **Stuck-disabled buttons on save failure.** `_on_distill_done` and `_on_consolidate_done` early-return on `save_memory` exception without re-enabling buttons. User sees Settings dialog with buttons greyed out and no way to retry without closing+reopening.

4. **Per-kin state dicts not migrated/cleared on rename/delete.** `_messages_since_distill`, `_distilling`, `_distill_queue`, `_walking_from_start`, `_soul_cache`, `_memory_cache` all leak entries keyed by old kin names. Recreating a deleted kin with the same name inherits stale counters.

5. **`distill_offsets` shallow-merge on config load.** `load_agent_config` does `{**DEFAULT_AGENT_CONFIG, **data}` — nested dicts (`voice`, `distill_offsets`) get replaced rather than merged. New fields added to DEFAULT_AGENT_CONFIG don't apply to existing kin configs.

6. **Snapshot-load corruption.** `_on_open` mutates `self.conversation` but doesn't reset `_persisted_msg_count`. Next persist call corrupts `conversation.jsonl` with hybrid `[old kin head] + [snapshot tail]` content.

7. **Approval-handler atomicity.** Telegram `/allow` / `/deny` reads pending approval under lock but mutates outside. Two near-simultaneous responses can both resolve the same approval, overwriting each other.

8. **OpenRouter cost-estimate ignores cache discount.** `_estimate_call_cost` multiplies full prompt tokens by full price even when 99% were cache reads. `real_cost` is in usage.log now, so this is less load-bearing — but `est_cost` lies systematically for Ollama-only kin (no real_cost) and confuses budgeting.

## hearthkin.pyw

### Critical

**H1. `_on_open` corrupts kin auto-persist file after loading a snapshot** — *hearthkin.pyw:4609-4634*
After `self.conversation = cleaned`, `_persist_current_conversation()` is called but `_persisted_msg_count` still holds the prior kin's value. Append-only fast path appends `cleaned[persisted:]` to disk — but `conversation.jsonl` still contains old messages at the head. Result: corrupted hybrid file. Permanent data corruption whenever the user opens a snapshot.
**Fix:** Reset `_persisted_msg_count = 0` + force-rewrite via `save_agent_conversation` (already imported, unused at line 146). Also update `_conversation_mtime_seen` and `_render_window`.

### High

**H2. `_on_open` leaves `_render_window` stale** — *hearthkin.pyw:4626-4628*
After loading a snapshot, render window isn't recomputed. If the new file is longer than the prior window, only the prior-window slice paints.
**Fix:** Recompute `_render_window` from `config["chat_history_window"]` clamped to `len(cleaned)`.

**H3. `_walking_from_start` is never initialized in __init__** — *hearthkin.pyw:6910, 7031*
Only ever read via `getattr(self, "_walking_from_start", None) or {}`. Mutations via the redistill handler do `self._walking_from_start[(kin, scope)] = True` which works, but any path that uses `.setdefault` directly would AttributeError. Inconsistent state model.
**Fix:** Initialize `self._walking_from_start = {}` in `__init__` near `_distill_queue` (line 488).

**H4. `_on_delete_agent` doesn't clear distillation state for the deleted kin** — *hearthkin.pyw:2809-2836*
`delete_agent(name)` removes from disk, but `_messages_since_distill`, `_distilling`, `_distill_queue`, `_walking_from_start`, `_soul_cache`, `_memory_cache` retain entries keyed by deleted name. Reusing the name inherits stale counters.
**Fix:** Sweep per-kin state dicts for keys matching the deleted name (including tuple keys).

**H5. `_on_rename_agent` doesn't migrate per-kin state dicts** — *hearthkin.pyw:2738-2807*
Same family as H4. After rename, in-memory state keyed by old name is orphaned; counters reset silently.
**Fix:** Re-key tuple entries `(old, *) → (new, *)` and singular old-name keys.

**H6. `_render_conversation` walk-back loop doesn't isinstance-guard** — *hearthkin.pyw:5245-5246*
`while i > 0 and self.conversation[i].get("role") != "user"` — if conversation has no user messages or malformed first message (non-dict), the walk attempts AttributeError.
**Fix:** Wrap with `isinstance(self.conversation[i], dict)` check.

**H7. `_request_exec_approval` race on shutdown** — *hearthkin.pyw:7706-7742*
If shutdown fires between the top `_closing` check and the `_pending_approvals.append`, the worker blocks forever on `wait()` and Hearthkin won't exit.
**Fix:** Re-check `_closing` after appending; if true, remove and return deny.

**H8. `wx.CallAfter` chunk handlers don't check `_closing`** — *hearthkin.pyw:3544-3547, 6176-6178*
Worker threads fire `wx.CallAfter` for every chunk; close-during-stream queues callbacks against destroyed widgets.
**Fix:** Add `if self._closing: return` to each `_on_*_chunk` / `_on_*_done` handler.

**H9. `_run_tool_loop_inline` worker doesn't check `_closing` before painting** — *hearthkin.pyw:3601-3620*
Same family as H8.

### Medium

**H10. `_on_consolidate_done` returns without enabling buttons on save failure** — *hearthkin.pyw:6504-6508*
`save_memory` exception path sets status and returns without re-enabling `consolidate_btn` / `distill_btn` (disabled in kickoff). User left with both buttons stuck disabled.

`wx.CallLater(4000, ...)` replaced but not stopped during `_on_close`. Could fire against destroyed widget.

**H20. `_persist_current_conversation` swallows snapshot exception class info** — *hearthkin.pyw:4044-4066*
Snapshot failure flag overrides main auto-persist success flag. Status mismatch.
**Fix:** Track main vs snapshot save success separately.

## kin_persistence.py

### Critical

**P1. Migration silently empties conversation on bad legacy JSON shape** — *kin_persistence.py:1430-1437*
`load_agent_conversation` → `_migrate_legacy_json_to_jsonl`: bad legacy `.json` shape (truncated, top-level string) silently treats as empty; rename archives only good copy as `.bak`. Conversation appears wiped, no diagnostic.
**Fix:** Skip rename when `cleaned` is empty but parsed `msgs` was non-empty; or log via `append_failure_log`.

**P2. Telegram history migration partial-failure data loss** — *kin_persistence.py:1571-1628, 1488-1535*
`pop_user_history` atomic, but append loop acquires/releases conversation lock per entry. Mid-loop failure: slice gone from bot AND partially written. Un-appended remainder lost from both.
**Fix:** Hold lock once around whole loop, OR persist popped slice to staging file before iterating, OR re-stash remainder on failure.

### High

**P3. `load_json` swallows ALL exceptions silently** — *kin_persistence.py:705-711*
Returns `dict(default)` on any failure (corrupt JSON, permission, encoding). Corrupted `~/.hearthkin/config.json` silently resets all prefs to defaults with no breadcrumb.
**Fix:** Log to `save_failures.log` (or new `load_failures.log`) when `path.exists()` but parse fails.

**P4. `_load_conversation_jsonl` bare `except Exception: pass`** — *kin_persistence.py:1361-1382*
Per-line JSON decode error is intentional (truncated trailing), but outer except swallows PermissionError, UnicodeDecodeError. A conversation.jsonl rewritten as cp1252 (Notepad save) yields zero messages silently.
**Fix:** Use robust_decode fallback, log via `append_failure_log` on outer exception, count skipped lines.

**P5. `append_agent_conversation_turn` not wrapped in try/except** — *kin_persistence.py:1463-1485*
PermissionError or full-disk OSError raises through to callers (cron worker, Telegram bot, UI). Transient disk issue crashes the bot worker.
**Fix:** Wrap write, call `append_failure_log` on error, return cleanly.

**P6. `save_agent_conversation_preserving_externals` can duplicate messages** — *kin_persistence.py:1538-1568*
Splice logic trusts `known_count` matches `len(conversation)` at call time. If `conversation` was mutated between snapshot and call, splice DUPLICATES messages.
**Fix:** Dedupe by content hash on splice, or document the contract.

**P7. `load_base_prompt` regenerates on read failure** — *kin_persistence.py:1240-1264*
Seeds on first access AND on `except: pass` from existing-file read failure. User customizations silently reverted to defaults on any transient inaccessibility.
**Fix:** Only seed when file is missing, never on read-failure; log read failures.

### Medium

**P8. `load_agent_config` shallow-merge breaks new nested fields** — *kin_persistence.py:1152-1175*
`{**DEFAULT_AGENT_CONFIG, **data}` — nested dicts (`voice`, `distill_offsets`) get fully replaced rather than merged. New fields in DEFAULT_AGENT_CONFIG don't apply to existing configs.
**Fix:** Deep-merge nested dicts (extend the `telegram` pattern at line 1159).

**P9. `load_soul`, `load_memory`, `load_distill_prompt` use strict UTF-8** — *kin_persistence.py:1196-1217*
Bare `except: pass` → returns default. cp1252-encoded soul.md (Notepad on Windows) silently swaps kin's persona for placeholder. CLAUDE.md states "tolerant decoding for any file we read" as convention; these don't follow it.

**P10. `load_room_conversation` / save_room_conversation have no locking** — *kin_persistence.py:1884-1898*
Same race that motivated kin locks (cron+regen) can corrupt room conversations.
**Fix:** Extend `_get_conversation_lock` to accept room namespace, or add separate `_room_locks` dict.

**P11. `atomic_write_text` has no retry on Windows file-lock races** — *kin_persistence.py:683-698*

**Fix:** Short retry loop (3×100ms) around `os.replace` for PermissionError on Windows.

**P12. `_migrate_legacy_json_to_jsonl` rename failure leaves orphan `.json`** — *kin_persistence.py:1385-1418*

**P13. `_clean_chat_message` doesn't validate tool_calls shape** — *kin_persistence.py:1267-1350*
`tool_calls` preserved as-is when role=assistant. Malformed entries (missing `id`/`function`) get through; downstream 400s with provider.
**Fix:** Validate required keys per tool_call; drop field (or message) if malformed.

**P14. `create_agent` shallow-copies DEFAULT_AGENT_CONFIG** — *kin_persistence.py:1681-1691*
Nested `telegram` and `voice` dicts aliased to module-level defaults. Mutation before write contaminates defaults.
**Fix:** Use `copy.deepcopy(DEFAULT_AGENT_CONFIG)`.

**P15. `clone_agent` carries source's distill_offsets** — *kin_persistence.py:1694-1799*
Clone inherits full conversation.jsonl AND distill bookmarks pointing at it. Surprising "fresh kin" semantics.
**Fix:** Document carry-over, or add opt-in "reset conversation/memory" flag.

**P16. `parse_usage_log` reads entire file into memory** — *kin_persistence.py:758-819*
Already flagged in docstring; usage.log isn't rotated, slow Usage tab open + memory spike for heavy users.
**Fix:** Stream from the end with a deque, or implement log rotation.

## llm_backend.py

### Critical

**L1. `_chat_openrouter_blocking` retries empty responses without cost guard** — *llm_backend.py:1607-1611*
Bare `time.sleep(0.5)` retries unconditionally. Combined with `run_tool_loop` up to 8 iterations, a 200-empty cascade bills `MAX_TOOL_ITERATIONS × 2 = 16` calls. Some providers bill 200-empty too. Cost amplification.
**Fix:** Track cumulative empties per tool-loop iteration; cap retries via session token. Check `usage.cost` from empty response; bail loudly on billed-but-empty repeats.

**L2. Debug logging in hot SSE loop** — *llm_backend.py:1547-1551*
`import logging` + `getLogger` + `isEnabledFor` + `json.dumps(delta)` per chunk. If DEBUG enabled anywhere in process, json.dumps runs hundreds of times/sec on reasoning models. CPU saturates SSE consumer, back-pressures socket.
**Fix:** Module-level `import logging` and `_log`. Guard json.dumps with `if _log.isEnabledFor(logging.DEBUG)` BEFORE the call.

### High

**L3. Connection-cache retry without idempotency check** — *llm_backend.py:1340-1343*
POST retry on OSError assumes idempotent. If `conn.request` succeeded but `resp.read` failed partway, server may have processed and charged; retry sends second identical POST. No Idempotency-Key.
**Fix:** Add `Idempotency-Key` UUID per logical call, or only retry when `conn.request` itself raised.

**L4. `_estimate_call_cost` ignores cache discount** — *llm_backend.py:986*
Multiplies full `prompt_tokens × prompt_price`, ignoring `cached_tokens`. Anthropic's cache read is 1/10 fresh price; with 99% cache-read ratio, overstates by ~10x. Docstring claims "upper-bound" but applies no cache discount.
**Fix:** Pass `cached_tokens` into `_estimate_call_cost`; pull `pricing.input_cache_read` from catalogue.

**L5. Terminal `done` Chunk yielded after `finally` close** — *llm_backend.py:1571*
If `_stream_with_usage` raises during logging on done chunk, generator already closed. Consumer never sees `done=True`. Streaming state doesn't clear.
**Fix:** Move `yield Chunk(done=True, ...)` inside try block.

**L6. Multi-frame usage events overwrite each other** — *llm_backend.py:1539-1542, 1564-1565*
Some OR responses send usage on multiple SSE events. Code unconditionally overwrites `final_usage`. Wrong value wins if terminal lacks `cost` but earlier had it.
**Fix:** Only accept final usage frame (carrying `prompt_tokens > 0`); accumulate `cost` separately.

**L7. `run_tool_loop` max-iteration fallback re-calls without tools** — *llm_backend.py:2218*
Final fallback passes no `tools`. Schemas missing from budget reservation; `num_predict` still 8000. Budget math wrong-direction.
**Fix:** Pass `tools=tools` so budget includes schemas, OR lower num_predict so budget math doesn't over-reserve.

**L8. `done=True` Chunk has no content — consumers may drop usage** — *llm_backend.py:1571, 1029*
Filtering `if not chunk.content and not chunk.thinking: continue` skips done frame. Mitigated by `_stream_with_usage` logging before yield, but fragile.
**Fix:** Comment in `Chunk` docstring that done-Chunks must not be filtered.

### Medium

**L9. XML tool-call regex matches across unrelated content** — *llm_backend.py:1907-1908*
`<tool_call>\s*(\{.*?\})\s*</tool_call>` with re.DOTALL. Model writing `<tool_call>` in markdown code (e.g. explaining the format) → extraction and execution. Prompt-injection-by-history risk.
**Fix:** Boundary anchors `(?:^|\n)\s*<tool_call>`, or run extraction only when structured channel produced nothing.

**L10. `cache_control` mutates messages dict in place** — *llm_backend.py:1234-1249*
System message mutated from str to list of content blocks IN PLACE on `messages` param. Callers reusing the list (e.g. `run_tool_loop` history) get permanently mutated. Cache_control duplicates over iterations.
**Fix:** Deep-copy system message before mutation, or check whether cache_control already present.

**L11. Truncation floor of 512 too small after divisor** — *llm_backend.py:380*
`max(512, int(est_budget))` — small num_ctx + high ratio → 512 budget → drops all non-system turns except most recent.
**Fix:** Raise floor to 2048; surface warning when budget would have gone negative.

**L12. Truncation while-loop is O(N²)** — *llm_backend.py:281*
`_est_tokens(system + others) > max_tokens` recomputes over full list each iteration. For long histories, can lag UI thread after kin-switch.
**Fix:** Compute initial total once; subtract dropped message's `_message_text` length on each pop.

**L13. Calibration ratio EMA not weighted by sample count** — *llm_backend.py:565-583*
Fixed 0.5/0.5 weighting. Single outlier shifts ratio by half its delta in one step. Truncation budget oscillates.
**Fix:** Lower new-sample weight (0.2/0.8), or track sample-count and use 1/N for first few then settle.

**L14. Key file parse error swallowed silently** — *llm_backend.py:166-170*
`resolve_provider_key` returns `""` on parse error. User hand-edits the JSON file and corrupts it; only sees "No API key" errors with no hint that file exists.
**Fix:** Log parse failure to save_failures.log, or surface typed error.

**L15. Ollama HTTP fallback timeout hardcoded at 300s** — *llm_backend.py:1085-1089*
Wedged local Ollama on str-args fallback hangs worker for 5 minutes, past 60s watchdog.
**Fix:** Parameterize; default closer to streaming watchdog (~120s).

**L16. Pydantic fallback predicated on `tools` presence** — *llm_backend.py:1115*
Tool-less calls to Ollama can fail with cryptic pydantic errors on other shape mismatches.
**Fix:** Widen fallback (with one-retry flag), or document why tools-only is the cut.

**L17. Tool-call accumulator never surfaced** — *llm_backend.py:1671-1684*
`_accumulate_tool_call` builds complete per-call dict but accumulator is never yielded. Consumers see raw deltas. Hearthkin's tool path uses non-streaming so this hasn't bitten; future streaming-tools surface would build it wrong.
**Fix:** Yield accumulator on done chunk (extra Chunk field), or delete + docstring.

### Low

**L18. Env var transform** — `provider_name.upper().replace("-", "_") + "_API_KEY"`. Whitelist `[a-z0-9_-]` or raise on weird shapes.

**L19. Key file written world-readable on POSIX** — `os.chmod(key_file, 0o600)` after write.

**L20. Model catalogue fetch has no timeout retry** — first chat-send after launch can stall up to 30s. Async-fetch on launch.

**L21. Pricing parse swallows ValueError per-model** — non-numeric `pricing.prompt` (e.g. `"varies"`) → re-scans forever. Cache `(None, None)` too.

**L22. `_mark_used` re-cache race — already safe by accident** — clarify comment.

**L23. Idle-evicted conn dropped without diagnostic** — optional debug-log of hit/miss/evict ratios.

**L24. `num_predict < 8000` floor doesn't reserve for non-tool path** — tie reserve to num_predict rather than tools presence.

**L25. SSE `[DONE]` break leaks pending tool-call accumulator** — for providers without terminal usage, calibration silently no-ops. Fall back to OR's `/api/v1/generation/<id>` lookup, or log the gap.

## telegram_bot.py

### Critical

**T1. `/clear`, `/new`, `/reset` mutate `_histories` without lock** — *telegram_bot.py:1088, 1188-1191, 1245-1248*
The lock-discipline gap missed by v0.2.28's concurrency sweep. Inference worker can simultaneously write a new turn to the same dict.
**Fix:** Wrap each in `with self._histories_lock:` blocks.

**T2. `_load_history_for` hidden mutation via `setdefault`** — *telegram_bot.py:1672*
`self._histories.setdefault(user_id, [])` is a mutation that races inference + /clear without lock. Treating read as hidden write breaks lock discipline.
**Fix:** Take lock, use `.get(user_id, [])` (pure read), copy out under lock. Match `_load_group_history` pattern.

**T3. `_append_group_history` (share-off) save not wrapped in try/except** — *telegram_bot.py:2581*
Every other persistence call wrapped; this one isn't. Disk-full / permission error raises through, lands in broad handler at 2505 with misleading log.
**Fix:** Wrap, call `append_failure_log` with specific tag.

### High

**T4. `_cmd_regen` / `_cmd_undo` load+truncate not atomic** — *telegram_bot.py:1396-1402*
Load via `_load_history_for` then truncate. New message arriving between load and truncate produces inconsistent history.
**Fix:** Hold lock from `_last_user_index` through `_truncate_history_for`.

**T5. `pop_group_history` keys_to_try misses int forms** — *telegram_bot.py:2600*
Only tries f-string forms. If chat_id ever stored as Python int directly, pop misses it.
**Fix:** Try bare int and str forms too, or audit storage to guarantee f-string only.

**T6. `_request_exec_approval_telegram` race when evicting existing approval** — *telegram_bot.py:2935-2939*
Evicts existing pending then immediately replaces. Old worker pops new approval entry while new worker still waits. Back-to-back approvals from same user → second hangs 10min to auto-deny.
**Fix:** Conditional pop with identity check (`if pending is the_one_we_set`).

**T7. Approval-response handler atomicity gap** — *telegram_bot.py:804-808*
Reads `pending` from `_pending_approvals` under lock but mutates outside. Two near-simultaneous responses both see same `pending`, both set decision.
**Fix:** Atomic pop in handler (`pending = self._pending_approvals.pop(user_id, None)`). Worker's own pop becomes no-op cleanup.

**T8. `_cmd_status` context estimate misses tool_calls.arguments** — *telegram_bot.py:1326-1328*
Only counts `m.get("content")`. CLAUDE.md flags this as the structural overspend cause. /status displays wrong percentage.
**Fix:** Reuse `llm_backend._message_text` / `_est_tokens` including tool_calls JSON.

**T9. `_user_tool_bucket` falsy-or pattern hides empty-list buckets** — *telegram_bot.py:1748*
`ut.get(str(user_id)) or ut.get(user_id) or "none"` — empty-list custom override falls through to "none."
**Fix:** `ut.get(str(user_id), ut.get(user_id, "none"))`.

### Medium

**T10. `_is_bot_addressed` permanently fails when `_bot_user_id` startup-fetch fails** — *telegram_bot.py:2083-2105*
No retry. Bot can't engage in groups until restart. No diagnostic.
**Fix:** Retry in poll loop or first successful getUpdates. Log failure.

**T11. `_bot_username = None` edge case** — *telegram_bot.py:2099*
Bots without @username silently degrade to reply-only; no warning.

**T12. `stop()` join timeout vs long-poll** — *telegram_bot.py:509-515*
`getUpdates` long-poll is 35s; join timeout 1.5s. Shutdown returns with poll thread still running; offset advances past updates that get dropped.
**Fix:** Don't advance offset if `_stop.is_set()`. Or shorter long-poll.

**T13. Offset advances before queue.put** — *telegram_bot.py:677-678*
If put raises, offset advances past unprocessed update. Low probability but defense-in-depth.
**Fix:** Advance after successful put. Consider max queue size.

**T14. `_cmd_status` num_ctx fallback hides misconfigured 0** — *telegram_bot.py:1314*
Fallback to 8192 hides `num_ctx=0` which `_max_context_tokens` clamps to 512. /status shows 5% usage; real prompt gets brutally truncated.
**Fix:** Use same value `_max_context_tokens` will see.

**T15. `keep_typing` "once per session" is actually once per turn** — *telegram_bot.py:1798-1822*
`logged_failure = False` is in closure of one turn. CLAUDE.md and comment claim once per session.
**Fix:** Move flag to instance state, OR update docs.

**T16. `_wrap_exec_for_telegram` allowlist precedes denylist** — *telegram_bot.py:2891*
Allowlisted command matching denylist runs anyway. Exact-string match limits blast radius, but escape from future denylist tightening.
**Fix:** Check denylist first; deny regardless of allowlist.

**T17. `_format_tool_args` tautological branch** — *telegram_bot.py:2980*
Both branches identical; gratuitous quotes on string values.
**Fix:** `s = v if isinstance(v, str) else json.dumps(v, ensure_ascii=False)`.

**T18. `legacy_sender_re` recompiled per group message** — *telegram_bot.py:2367-2368*
Hot-path recompile of static pattern.
**Fix:** Module level.

**T19. `_cmd_clear` for share-with-desktop bypasses lock-aware save** — *telegram_bot.py:1059-1085*
Uses `save_agent_conversation([])` not `save_agent_conversation_preserving_externals`. Races with cron writes.
**Fix:** Use lock-aware variant, or document intentional /clear-wins-over-external behavior.

**Closed without action (speculative, comment-only, or design questions):**
- **H20, H25** ⊘ — `_persist_current_conversation` status-message nuance when snapshot fails after main succeeds. Low impact; the operator sees "saved" + a status flicker but data isn't lost. Not worth refactoring the status pipeline.
- **P6** ⊘ — `save_agent_conversation_preserving_externals` splice duplication concern requires the caller to mutate `conversation` between snapshot and call, which no in-tree call site does. Documentation-only.
- **P15** ⊘ — `clone_agent` carrying `distill_offsets` is correct by design: the clone inherits the source's conversation.jsonl, so the bookmarks pointing into it are still valid. Resetting them would cause the clone to re-distill content already in memory.md, which is the wrong direction.
- **P23, P24** ⊘ — `attachment_abspath` rejection reason logging and `DEFAULT_ROOM_CONFIG` preventative deep-merge. Cosmetic / preventative for code that doesn't have the failure modes yet.
- **L3** ⊘ — Idempotency-Key UUID on retry. Would prevent double-billing on a partial-read retry, but the retry only fires on OSError (connection-level failure) and the existing in-flight `Request-sent` guard already covers the realistic case. Real OpenAI/Anthropic idempotency keys are a structural addition (every payload, every model, schema for response replay) — not worth doing in the cached HTTP layer alone.
- **L8** ⊘ — Comment-only: "consumers must not filter the done Chunk." All current consumers handle it correctly; a regression test would be more useful than a docstring.
- **L12** ⊘ — Truncation while-loop O(N²). Real but only matters for very long histories. The per-kin lock around the call serializes it anyway; nothing's measurably blocked on it today.
- **L16** ⊘ — Widening the pydantic fallback to non-tool calls. Speculative — the current narrow trigger only fires when we know tools were the cause, widening risks masking unrelated bugs.
- **L22, L23, L25** ⊘ — Diagnostic / logging-only enhancements for connection-cache events that don't currently produce wrong behavior.
- **T15** ⊘ — `keep_typing` failure flag is already correctly documented as per-turn; the comment was updated during v0.4.4. The audit was reading a stale state.
- **T20** ⊘ — `_allowed_users` treats `"*"` as universal-allow. Foot-gun only if an operator types `"*"` into the allow_from UI, which the dialog prevents. The literal "*" is documented behavior.
- **T23** ⊘ — `f"user_{id}"` rendering `"user_None"` when sender id is missing. Cosmetic; senders without an id don't reach this path in practice (Telegram messages always carry a sender id).
- **T24** ⊘ — Group history trim asymmetry between share/non-share. Working as intended — share-with-desktop groups feed the unified conversation.jsonl which has its own size handling; non-share groups have their own per-group HISTORY_CAP.
- **T25** ⊘ — `/status` in groups. Feature request, not a bug — slash-commands in groups are deliberately the bot-info-only subset (per v0.4.4's group menu fix).
